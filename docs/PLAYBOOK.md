# PLAYBOOK — 让 AI 当真玩家的硬知识

> 验证环境：**Windows 10/11 · Stardew Valley 1.6.15 · SMAPI 4.5.2 · 本地联机（host + 1 farmhand）**
> 所有数字都来自我们自己的实测（样本很少），不是估算，也不是规格。
>
> ⚠️ **全部流程处于试验阶段。** 除特别注明外，每一节都是少量样本下的粗略验证，**没有一条被完整核实**。
> 下面写的"实测值"意思是"我们量到过一次或几次"，不是"稳定复现的规格"。拿它当参考，别当契约，用前先备份存档。

---

## 0. 一句话原则

**"脚是真相"**：一切读写都以"角色真的走过去了 / 真的按了键 / 真的弹了菜单"为准。
接口说的、缓存记的、猜的，都不算。冲突时以现场为准，然后去修缓存。

---

## 1. 桥的接口契约

本项目的感知全部来自一个本地 HTTP 桥（默认 `http://localhost:7850`）。它必须提供：

| 端点 | 用途 | 关键字段 |
|---|---|---|
| `GET /state` | 当前全局状态 | `location.name`、`player.x/y`、`player.isMoving`、`player.isInBed`、`time.dayOfMonth`、`time.timeOfDay`、`player.money`、`player.stamina` |
| `GET /surroundings?radius=N` | 以玩家为中心的格子视野 | 每格 `{x, y, passable, kind, ...}` |
| `GET /menu` | 当前打开的菜单 | `type`（如 `Billboard`、`Shop`）、选项列表、对话全文 |

**四条必须记住的坑：**

1. **必须用 `localhost`**。桥对 `127.0.0.1` 会返回 **400**（Origin 校验）。
2. `/surroundings` 的 **radius 硬上限是 30**（61×61 窗口）。传 100 也只给 30，不会报错——所以别以为你没看清是因为半径给大了。
3. `/surroundings` **只返回"有内容"的格子**。矩形里没返回的格，含义是"没信息"，不是"可走"。要主动当成 unknown 去测（见 §5）。
4. `/menu` 有 **2 秒级超时**。超时当"没菜单"，不要当崩溃。

> 桥本身不在本仓库（见 [DEPENDENCIES](DEPENDENCIES.md)）。自己实现时按上表对齐即可。

## 2. 输入层：为什么只有一种按键方式有效

> ⚠️ **本节只做过粗略测试，没有完全核实。**
> 下表是**同一台机器、同一个游戏版本、少量样本**下的观察结果。`SendInput` 在不同 Windows 版本、
> 不同输入法、窗口是否前台、游戏是否以管理员运行等条件下都可能表现不同；我们**没有**逐项复测。
> 结论只当"我们这边看到的现象"，不作定论。要依赖某条路径，请自己在你的环境里再验一遍。

| 方式 | 结果 |
|---|---|
| `SendInput` / `keybd_event`（真键盘事件） | **游戏不认** |
| `SendKeys` | 不认 |
| `PostMessage(WM_KEYDOWN + WM_CHAR + WM_KEYUP)` 打到**带 mod 的实例** | **有效** ✅ |
| 真实光标 + `mouse_event` / `SetCursorPos` | 有效（标题画面、对话框选项） |
| 直接 `SetCursorPos` 点击游戏内世界 | 有效，但坐标要 DPI 感知 |

推论：
- 键盘走 `PostMessage`，三连（DOWN → CHAR → UP）缺一不行；
- 鼠标要真的移动光标（很多 UI 只认 hover 再 click）；
- **文字输入只吃真键盘**：改名、输 IP 这类，要么用剪贴板，要么改存档，别指望 PostMessage。

`scripts/keyer.ps1` 是常驻进程，协议 `<hwnd-hex> <key> <holdMs|down|up>`——`down`/`up` 是为了长按走位。

## 3. 定位：句柄、DPI、标题

**找窗口别靠记忆，靠标题。** 带 mod 的实例标题长这样：

```
Stardew Valley 1.6.15 - running SMAPI 4.5.2 with N mods [main player]
```

- 认 `[main player]`，**别认 `with 3 mods`**——别人多装一个 mod 你就永远找不到窗口了（这是原始实现踩过的坑，已在 `gethwnd.ps1` 修正）。
- **句柄手抄会错**：`0x2f04c0` 和 `0x2f0480` 差一位，`PostMessage` 依然返回成功，但角色纹丝不动——表现得像"游戏卡死"。**一律现场取句柄**。
- 读窗口矩形必须 **`SetProcessDPIAware()`**，否则 1302×776 会被读成 868×517，所有点击按比例偏。

## 4. 走位：长按 + 轮询

单发按键走一格太慢（约 1.5 s/格）。改成：

```
down(方向键) → 每 60 ms 读一次 player.isMoving / x,y → 到位就 up
```

实测 ≈ **0.35 s/格**（跨图 110 格 39.3 秒，约 50 游戏分钟）。

- **松手时机**：目标格到了立刻 `up`，别等"看着差不多了"——惯性会多走半格。
- **`isMoving` 为假不代表到了**：可能被挡。所以判定要用坐标，不用动画状态。
- 残键要清：异常退出前一定 `up` 所有按下的方向，否则角色一直往一个方向飘。

## 5. 感知：unknown 不等于可走

地图窗口内每格只有三种可信来源：

1. `/surroundings` 说它有东西（墙、树、水、家具…）；
2. 我们**真的站上去过**（这是最高优先级证据）；
3. 都没有 → **unknown**，代价按"未知"算（+2 秒探格），而不是按"可走"算。

这条规则救过很多次：地图边界、家具缝、门廊，接口经常报 `passable:false`，但人明明能走过去。**走过一次就把它钉成证据**，并且设 TTL 让它过期重测。

## 6. 地图持久化

路径：`<savesDir>/<saveFolder>/pathmap/<Location>.json`（每张地图一个文件）。

每格一条：

```jsonc
{
  "state": "walkable | block | unknown",
  "kind": "grass | tree | water | warp | door | ...",
  "cost": 0.2,          // 秒/格
  "need": "walk_blocked | clear_failed | ...",  // 为什么是 block
  "src": "event | scan | guess",  // 证据来源，event 优先级最高
  "at": 1790000000,     // 记录时间
  "dd": 54,             // 记录时的游戏日
  "strikes": 0,         // 连续矛盾次数
  "ttlDays": 3
}
```

规则：

- **代价表**：走 `0.2`；可清理（杂草/小石头/树枝）`0.2 + 清理时间 ≈ 0.5`；不可通行 = 无穷；未知 `+2.0`。
- **脚是真相**：走过/站过的格盖 `src:"event"`，`look` 扫描不能把它改回墙。
- **三振**：同一格连续 3 次"接口说不可走、实际走过去了"→ 记 `block` 并 `ttlDays:1`，次日重测。不然会在门口和树之间无限乒乓。
- **代价衰减**：换季、绿雨、砍树之后旧结论会失效，靠 TTL 自动过期。
- **不可达要早退**：A\* 找不到路时返回 `unreachable:<原因>:<最近可达格>`，而不是原地打转烧预算。

---

## 7. 跨图

- 地图之间靠 **warp 格**连接。warp 格在"格子是否可通行"上经常被报成 `block`（因为它是个传送物），**A\* 必须放行 warp 格**，否则永远到不了隔壁。
- warp 目标可能在地图边界外（`x == 地图宽度`），越界检查要专门放行这一种。
- 跨图移动时，**边界的另一侧**要重新扫描，别拿上一张图的结论套。

## 8. 农活

| 动作 | 前置 | 判定成功 |
|---|---|---|
| 浇水 | 手持水壶、站相邻格、面朝作物 | 回读该格 `watered:true`；水壶空要自动补水 |
| 收割 | 作物 `harvestable:true`、背包有空间 | 回读该格作物消失 + 背包数量增加 |
| 清障 | 对应工具在手、目标可清理 | 回读该格变 `walkable`（**注意：掉落物≠清障成功**，见 §10） |
| 播种 | 地面已锄、种子在背包 | 回读该格 `crop` 出现 |

- 任何一步失败都要**明确原因**（工具不在手 / 被挡 / 体力不足 / 目标消失），不要静默重试。
- 体力：低于 15% 停止批量农活，别把角色干趴下。

## 9. 收工：用"返程时间"倒推

不要写死"22:30 必须回家"，除非你只有这一条路。更稳的做法：

```
收工时刻 = 目标就寝时刻 − max(30 分钟, 实测返程分钟 + 20 分钟)
```

- **实测返程分钟**：从当前位置到床的实际走行时间（我们量过 0.35 s/格 ≈ 0.058 游戏分钟/格，直接用格数估也行）。
- **返程估算的保鲜期**：缓存 30 分钟、偏离当前位置超过 12 格就作废，重算。
- **收不上就别开工**：`预计办完 = 现在 + 准备 + 行程 + 办事`。晚于店铺打烊/目标窗口，就不出门，改做附近能收尾的活。
- 到点还没回家 → 当天只做"往家走"这一件事，不要再接新目标。

> 这一节的算式结构参考了 [CSXizhang/star](https://github.com/CSXizhang/star)（Apache-2.0）的 `CompanionBedtime.ShouldWindDown`，参数按本项目实测重定。

## 10. 回执语义：别让"我做了什么"冒充"世界变了什么"

每次动作落一条记录，字段固定：

```jsonc
{
  "commandId": "uuid",
  "idempotencyKey": "uuid",       // 有副作用的动作必须有，重放同一 key 不重复执行
  "intent": "water 3 tiles at 42,58..60",
  "result": "confirmed | failed | unknown",
  "inventoryDelta": [{"name": "Parsnip", "delta": 5}],
  "skipped": [{"tile": "42,60", "why": "already watered"}],
  "remaining": ["42,61"]
}
```

三条铁律：

1. **`unknown` 不是成功**。断线/超时后先查终态（`/state` + 现场），查不到就停，不要"接着干"。
2. **清障目标数 ≠ 物品变化**。砍了 3 个障碍可能掉 12 木材、也可能掉 0；分别记。
3. **部分完成要保留**。批次跳过的格写进 `skipped`/`remaining`，下一轮从这里接。

> 字段结构参考了 [CSXizhang/star](https://github.com/CSXizhang/star)（Apache-2.0）的 protocol 设计（`idempotencyKey` / `commandResultQuery` / `inventoryDelta`），按本项目实现重写。

## 11. 坑清单（按被坑代价排序）

| # | 坑 | 后果 | 处理 |
|---|---|---|---|
| 1 | 句柄抄错一位 | 投键静默失效，像卡死 | 一律现场取句柄 |
| 2 | 信旧地图/旧现场 | 绿雨刷新、家具挪位、门被记成墙 | 出发前扫 10 格，撞了以现场为准 |
| 3 | 门/门廊被报不可通行 | 进不去也出不来 | 脚是真相 + warp 放行 |
| 4 | 醒来第一下按键被起床动画吃掉 | 第一步没动 | 醒来等 5 秒再动 |
| 5 | 床的触发点是"踏上去的那一格" | 站在旁边按没反应 | 走到床上再交互 |
| 6 | 三振记墙会误伤门口 | 门口被永久记成墙 | TTL 压到 1 天 + 出发前重扫 |
| 7 | warp 目标在地图边界外 | 越界检查直接拒绝 | 特判放行 |
| 8 | `/surroundings` 只返回有内容的格 | 把"没信息"当"可走" | 缺的补 unknown，代价 +2 s |
| 9 | resource clump 挡路但 `passable` 为真 | 一直撞 | 单独识别，记 block |
| 10 | 绿雨杂草被当墙 | 整片地不可达 | 按"可割杂草"分类 |
| 11 | SMAPI 控制台窗口盖住游戏 | 真点击被吃掉 | 先把控制台挪走 |
| 12 | 不做 DPI 感知读窗口 | 坐标全偏（×1/1.5） | `SetProcessDPIAware()` |
| 13 | 把 `/menu` 的 2 秒超时当崩溃 | 误判 | 当"没菜单"处理 |
| 14 | 端口是 DLL 里的常量 | 两个实例只有一个能绑 | 第二个实例用空的 `--mods-path` |
| 15 | 文字输入只吃真键盘 | 改名/输 IP 无效 | 剪贴板或直接改存档 |
| 16 | 存档显示名的两处 | 改了正文标题还显示旧名 | 正文 `<player><name>` + `SaveGameInfo` 都要改（本仓库不提供改存档工具，自己按这两处改，改前先备份） |
| 17 | PowerShell 传空字符串参数被吞 | `--mods-path ''` 失效 | `-Command "& { & '...' -ModsPath ([string]'') }"` |
| 18 | 联机里冻时间只冻自己 | 两边时钟错开 | 不做时间暂停/加速 |

## 12. 验收怎么算过（L1–L4）

| 层 | 叫什么 | 过线标准 | 证据 |
|---|---|---|---|
| **L1** | 手 | 5 个基础动作（走/交互/对话/开店/上床）全部有反应；每格 ≤0.4 s | 动作清单 + 3 段走行耗时 |
| **L2** | 眼 | 跨图一次到位；撞墙 0 次；同一格 3 次矛盾才记墙且 1 天后重测 | `go` 输出的 `bumps/secPerTile` |
| **L3** | 一起玩 | 浇水无漏无重、收割数对得上、采集不漏地、采购不超预算、全天按时收工 | 每项的"回读"结果 |
| **L4** | 挂机 | 无人值守走完一整天，翻日正常，断线能接 | 动作日志 + 次日存档 |

记录要求：**失败也写**。写清哪一条阻塞、阻塞多久、当时的现场。只写"通过"的记录没价值。
