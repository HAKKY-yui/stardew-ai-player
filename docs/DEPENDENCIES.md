## 关于那个桥（重点，有冲突自己解决）

我们用的是 **`JunimoBridge` 0.3.2，作者 `mlkgrnt`**。

- 它在我们这边是**只有 DLL，没有源码**的分发形式；
- `manifest.json` 里**没有许可字段**，目录里**没有 LICENSE 文件**；
- 按著作权默认规则，这属于**保留所有权利**。

所以：

1. **本仓库不会、也不能附带它**（包括 DLL、zip、反编译产物）。
2. 你需要自己去获取，或者**自己实现一个符合 [PLAYBOOK §1](PLAYBOOK.md#1-桥的接口契约) 契约的桥**。
3. 如果作者公开了仓库/许可，请直接去原处获取——**别找本项目要**。
4. 这个冲突我们没法替你解决，也不打算绕过。

> 想自己写桥：最小实现只要三个只读端点（`/state`、`/surroundings`、`/menu`），
> 用 SMAPI 的 `Console Commands` 或自己写一个 SMAPI mod 都能做到，工作量大概一两天。

## 环境不匹配时你会遇到什么（自己排查）

| 症状 | 先查 |
|---|---|
| 标题里没有 `[main player]` | 是不是从 SMAPI 启动的；是不是第二个实例（`--mods-path`） |
| `gethwnd.ps1` 说找不到窗口 | 标题文案变了（升级 SMAPI 后常见）→ 改 `gethwnd.ps1` 的匹配串 |
| 键发出去了角色不动 | 句柄对不对；窗口是不是在前台；是不是打到了 0-mod 实例 |
| 点击全偏 | 有没有做 DPI 感知；窗口位置是否和 `scripts/host.ps1` 里的 `$winX/$winY/$winW/$winH` 一致 |
| `/state` 返回 400 | 把 `127.0.0.1` 换成 `localhost` |
| `/state` 连不上 | 桥没起来 / 端口被另一个实例占了（端口是 DLL 里的常量） |
| 跨图永远 `unreachable` | warp 格是不是被记成了 `block`；目标是不是在地图边界外 |
| 原地来回横跳 | 三振阈值没生效；或者目标本身不可达，看返回里的 `<最近可达格>` |
| 联机里时间停住 | 别用时间暂停。客户端暂停只冻自己那份，两边会错开 |
| 改了角色名，标题画面还是旧名 | `SaveGameInfo` 没改——存档正文的 `<player><name>` 和 `SaveGameInfo` 是两处，都要改 |
